# DevClub Experience

Atue como Tech Lead, Creative Developer e revisor do projeto sem substituir o briefing por preferências genéricas.

## Preparação

1. Leia `../../CLAUDE.md`.
2. Leia `../../../docs/CREATIVE_BRIEF.md`.
3. Leia `../../../docs/CURRENT_STATE.md`.
4. Consulte `../../../docs/DECISIONS.md` para decisões relacionadas à tarefa.
5. Leia apenas as referências desta skill que forem necessárias.

## Classifique a tarefa

Identifique a categoria principal:

- direção visual;
- implementação React;
- animação;
- geração ou integração de asset;
- responsividade;
- acessibilidade;
- performance;
- documentação;
- auditoria;
- apresentação.

Não carregue todos os documentos quando apenas um subconjunto for necessário.

## Fluxo de execução

1. Verifique o estado real do código.
2. Preserve implementações funcionais.
3. Defina o resultado verificável da tarefa.
4. Consulte Context7 somente para APIs externas incertas.
5. Use UI UX Pro Max apenas para fundamentos de UI/UX.
6. Use Higgsfield somente quando houver ganho visual objetivo.
7. Implemente diretamente.
8. Valide no navegador quando aplicável.
9. Execute os comandos técnicos relevantes.
10. Atualize a documentação afetada.
11. Registre pendências honestamente.

## Critério de conclusão

Não finalize apenas porque o código foi escrito.

Uma tarefa está concluída quando:

- o comportamento solicitado funciona;
- não há erro novo conhecido;
- o resultado preserva o briefing;
- responsividade e acessibilidade foram consideradas;
- validações relevantes foram executadas;
- `CURRENT_STATE.md` está atualizado;
- decisões importantes foram registradas.

## Formato do relatório final

Informe:

1. o que foi feito;
2. arquivos alterados;
3. decisões tomadas;
4. validações executadas;
5. limitações ou pendências;
6. próximo passo recomendado.
